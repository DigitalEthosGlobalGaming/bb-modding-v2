---
name: bb-modding
description: Set up this Bloodborne Windows modding toolkit, generate private game references, or create native and content mods using its SDK and tools.
---

Read the repository README.md and docs/SETUP.md. Use the root containing setup.ps1;
all paths are relative to it. Run .\bb.ps1 doctor if .local/workspace.json exists.

For setup, obtain the user's game parent folder (contains CUSA03173/uroot) and installed
bbport folder (contains Bloodborne.exe). Run setup.ps1 with those two paths and
-NonInteractive; add -InstallPrerequisites only when prerequisite installation is authorized.
Use -ConfigureOnly for validation without tool installation or extraction.
The default full reference export needs at least 60 GiB free. -Mode scripts is smaller.

Game-derived output remains ignored. Use game-unpacked/raw for preserved archive extraction,
game-unpacked/decompiled for recovered Lua/HavokScript, and the original game assets as
Smithbox's input. Decompiled text is reference material, not proven equivalent source.
Do not put recovered game code into examples, patches in this repository, or agent docs.

For a native mod, read docs/MODDING.md, docs/RUST_SDK.md and sdk/include/bbmod.h, then use
.\bb.ps1 new-mod me.my-mod "My Mod". Build in mods/me.my-mod. Local catalogs require the
SDK local-catalogs feature and are generated by setup; without it, lookups return unknown.
Keep panic unwinding and host ownership of hooks/callbacks/resources across reloads.

For content work, read docs/CONTENT.md. Build overlays outside original game data.
For runtime builds, read docs/RUNTIME.md; older integration lacks newer backends.
Separate builds from deployment and preserve the printed rollback location when deploying.
Never infer gameplay validation from compilation or synthetic tests.

Before staging, run python src/scripts/audit_publication.py and review source provenance
under docs/PROVENANCE.md. User-authored personal mods belong to their own repositories.
